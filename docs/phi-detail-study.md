# Φ=0.4〜0.5の詳細計算

## 調べること

既存105試料では最大クラスタの成長がΦ=0.4〜0.5で大きく変化しました。
最大クラスタ1個を除く重み付き平均は、測定点中ではL=64/128でΦ=0.4、L=32で0.5が最大でした。
0.1刻みの結果だけではピーク位置を決められないため、0.41〜0.49を0.01刻みで追加します。
端点0.40/0.50は既存105試料の該当結果を使用し、再生成しません。
真のピークが0.4未満にある可能性も残るので、この走査で範囲外と分かれば低濃度側を追加します。

## 段階と試料数

| グループ | L | 新しい目標占有率 | seed数 | 試料数 |
|---|---|---|---:|---:|
| pilot_L64 | 64 | 0.42, 0.44, 0.46, 0.48 | 5 | 20 |
| detail_L32 | 32 | 0.41〜0.49、0.01刻み | 5 | 45 |
| detail_L64_remaining | 64 | 0.41, 0.43, 0.45, 0.47, 0.49 | 5 | 25 |

未実行の保存先で最初からfullを選ぶと、pilotを含め135試料を順次生成します。

## PCで実行するコマンド

Linux/WSLのリポジトリ直下で実行します。

```bash
git pull --ff-only
python3 scripts/run_phi_detail.py pilot
```

新しいネットワークの生成とCSV保存、gzip圧縮、H₂・平均クラスタサイズの解析、送付用ZIPの作成まで進みます。
C11コンパイラとMake、Python 3が必要です。Matplotlibは不要です。全試料の画像は作りません。
正常完了後の最後の表示は`SUCCESS: 20 samples, 4 conditions`です。
`UPLOAD THIS FILE:`の直後に表示される`upload_phi_detail_pilot.zip`を送ってください。

結果と負荷を確認した後、次を実行します。

```bash
python3 scripts/run_phi_detail.py full
```

こちらは`SUCCESS: 135 samples, 27 conditions`となり、pilotを含む追加135試料のZIPを出力します。
pilotとfullのZIPを両方受け取ったときは、同じ(L,Φ,seed)の20試料を重複して平均しないでください。
fullのZIP内には重複はありません。Φ=0.40/0.50の旧試料はこれらのZIPに含まず、別に受領済みの結果と合わせて比較します。

実行せず条件だけ確認する方法：

```bash
python3 scripts/run_phi_detail.py plan
```

保存先を別にする場合は`--output PATH`、別の実験設定を使う場合は`--config PATH`を指定します。
pilotからfullへ進む場合は同じ保存先を指定してください。

## 保存と再利用

既定の保存先は`data/refinement/phi040_050/`です。Git管理対象にしません。

- `study.json`：設定の控えと直近の完了状態。
- `<グループ>/simulation/`：既存benchmark処理が保存する全原データ・ログ・実行情報・ソースZIP。
- `<グループ>/analysis/`：元CSVの検証後に求めたH₂・クラスタ統計・サイズヒストグラム。
- `results_<pilotまたはfull>_<日時>/`：選択した完了グループをまとめたCSV/JSON/ZIP。

case番号は各グループで再開するため、統合CSVのcase_idを`group/original case_id`にします。
統計の条件は(L,目標Φ,seed)で照合し、重複を拒否します。
モデル・規格化・平均の定義は[H₂・クラスタ解析](h2-cluster-analysis.md)と同じです。
統合時にはシミュレーション実行ファイルのSHA256も一致することを確認します。

完了したグループの条件・完了状態・解析試料数が一致した場合に再利用します。
この「再利用」はグループ単位です。途中停止したグループ内の個々の試料から自動再開する機能はありません。
途中停止した実行や不完全な解析フォルダがあれば、その出力を残して停止します。エラー全文を送ってください。
同時実行を避けるため`running.lock`を使います。通常の終了・例外では解除し、強制終了で残った場合は自動削除しません。

元の105試料の保存先は変更しません。新規CSVは既存benchmarkの保持方針に従い、復号SHA256を確認後にgzipで保持します。
圧縮前のCSVバイト列は復元可能です。

## 条件・負荷・検証範囲

設定は`configs/experiments/phi040_050.json`を正本にします。
4腕・腕長5・A型確率0.5・開境界・既存の結合規則・seed=3,17,42,101,202を維持します。
試行上限はmax(10000,100×目標分子数)、C処理のタイムアウト180秒、RSS上限4096 MiB、
試料出力512 MiB、グループ出力3072 MiB、空き容量の下限2048 MiBです。
これらは既存benchmarkの監視による停止条件であり、OSの厳密なハード制限ではありません。
途中停止・目標未達を成功試料へ混ぜず、元CSV検証を通ったグループだけを統合します。
所要時間はPCの負荷・環境・占有率に依存し、手元PCでの実行前には確定しません。
同じseedを各占有率で使うため、条件間の試料の独立性を仮定せず、まず点ごとの平均とSDで比較します。

```bash
make test-detail
```

135条件の重複・端点除外、planが生成処理をしないこと、途中停止の保全を検証します。
小さなL=8のC計算を実行し、pilotからfullへ進んでも完成済みグループを再生成せず、解析・ZIP作成まで完了することも確認します。
この小規模検証を、PCのL=64/128の詳細計算を実行済みという意味にはしません。
