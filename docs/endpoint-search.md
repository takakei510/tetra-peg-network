# ③-A：末端の近傍探索（結合候補まで）

## 今回の仕様

3D立方格子、開境界、マンハッタン距離1～2にあるA-B末端を候補として列挙する。
距離の定義は今回の暫定採用条件。各腕の最終格子点が末端で、IDは `4*分子ID+腕ID`。
全末端を巡回し、同じ候補を両側から見つけてもIDの小さい側だけ保存する。
候補は距離条件を満たす潜在ペアであり、まだ結合していない。
一つの末端が複数候補を持つことは正常。1末端高々1結合の制約は次の③-Bで適用する。
UF、結合相手、結合率はこの段階では更新しない。

## データとアルゴリズム

- `EndpointIndex.endpoint_at_site[site]`：格子点から末端IDを引く配列。末端なしはSIZE_MAX。
- `CandidateStore.pairs`：候補ペアの動的配列。各組はendpoint_a < endpoint_b。
- `SearchStats`：相対位置を調べた回数と、境界内で索引を照会した回数。

生成完了後に索引を作り、軌跡・分子型と同じ状態のまま探索する。
分子を追加・変更したら索引を破棄して作り直す。古い索引の自動追跡は行わない。
中心や腕の途中は候補に含めない。元のowner配列と軌跡を変更しない。

探索開始時に、座標差(dx,dy,dz)が `1 <= |dx|+|dy|+|dz| <= 2` を満たす
24個のオフセットを作る。各末端の周囲の24点について、境界内なら索引を参照する。
異種末端を発見したらID順で重複を除いて候補へ追加する。途中の格子点が占有されているかは
結合候補の距離判定では調べない。結合を格子上の経路として生成する処理ではない。

計算量：索引の構築はO(L³+4N)、探索はO(24×4N+C)、Cは候補数。
追加メモリはO(L³+C)。size_tの索引は64ビット環境では格子1点あたり8バイト。
全末端対を比較するO(N²)処理は小規模テスト用だけに残す。
現在のデモは2分子だが、索引・探索APIは登録済み分子全体を処理する。

## 実行と保存

```sh
make test
python scripts/run_demo.py --mode candidates --config configs/demos/candidates_L8_seed3.cfg
```

既存の実行管理を直接利用し、`data/runs/<実行ID>/` に次を保存する。
設定コピー、軌跡CSV、metadata、run.json、コードの控え、候補CSV、候補入り画像。
`candidates.csv` は末端ID・分子ID・腕ID・型・格子点ID・座標・マンハッタン距離を持つ。
endpoint_aはIDが小さい方を表し、必ずA型という意味ではない。
候補0件でもヘッダー付きCSVを出力し、正常な探索結果として扱う。
候補CSVの読込・距離・型・軌跡との整合性を検査してから描画する。
緑点線は候補、青はA分子、赤はB分子。直線表示の長さがマンハッタン距離を表すわけではない。

実行例：L=8、各4腕5歩、A/B固定、開境界。

| seed | 分子数 | 末端数 | 占有点数 | 候補数 | 相対位置の確認 | 境界内索引照会 |
|---:|---:|---:|---:|---:|---:|---:|
| 3 | 2 | 8 | 42 | 3 | 192 | 169 |
| 12345 | 2 | 8 | 42 | 0 | 192 | 152 |

seed=3は候補を見やすくするため選んだ例。候補数の平均・分布や高速化倍率の測定結果ではない。
seed=12345は以前のL=8の生成条件を使った候補0件の例。

## 検証

`tests/test_endpoint_search.c` は人工末端配置と生成された6分子×50 seedで総当たりと照合する。
候補集合の完全一致、同型の除外、距離1・2を含むこと、距離3を含まないこと、
(1,1,1)をマンハッタン距離3として除外すること、開境界で反対側へ回り込まないこと、
候補の重複なし、格子・軌跡不変、末端0件を確認する。
人工配置は距離テスト用であり、生成した物理試料とは区別する。
索引構築は重複末端・範囲外末端・owner不一致をエラーにする。
これは候補探索の検証であり、ランダム結合の分布やゲル化の検証ではない。

## 次の区切り

③-Bでランダムな候補選択と1末端高々1結合を実装する。
候補ペアのシャッフルか、末端のシャッフル後に相手を抽選するかは分布が異なるため明示して決める。
同じ分子対の複数結合の可否もその段階で整理する。生成規則・腕の順序・境界条件は従来通り暫定。
