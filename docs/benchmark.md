# 系サイズを変えた性能測定

計算・Python後処理・描画・保存容量を分けて測り、PCでの実行範囲とサーバ利用を判断します。
LinuxまたはWSL、C11コンパイラ、Make、Python 3.9以降を使用します。描画する場合だけMatplotlibが必要です。
ベンチマーク自体にpsutilやGNU timeの追加インストールは不要です。

## 最初の実行

リポジトリのルートで実行します。

```bash
git pull origin main
python3 scripts/benchmark.py --config configs/benchmarks/pc-pilot.json
```

1回だけビルドした後、L=16,32,64,128、占有率0.1と0.3、各3seedの計24試料を**1試料ずつ**実行します。
腕長5・A型確率0.5・開境界を固定します。条件はJSONに保存し、未知キー・重複キー・不正値は拒否します。
C側の既存設定読込みを正本とし、目標分子数と切り捨て処理を重複実装していません。

出力先は`data/benchmarks/<UTC時刻_UUID>/`です。既存結果を上書きしません。
明示する場合は`--output data/benchmarks/pc-first`のように**新しいフォルダ名**を指定します。

## 測っている区間

| 段階 | 含める処理 | 時間とメモリの解釈 |
|---|---|---|
| `c` | 配置、候補探索、結合、UF、7 CSV書出し | Cプロセス全体。ビルドは含まない |
| `postprocess` | CSV読込み、整合性検証、BFS照合、最大成分・枝リスト抽出 | Pythonプロセス全体。画像は作らない |
| `plot` | CSVの再読込みと4 PNG生成 | プロセス全体に加え、読込みと描画保存の内部時間を記録 |
| 圧縮 | CSVのSHA256計算、gzip圧縮、復号ハッシュ照合 | `compression_wall_seconds`に別記。Cの時間には含まない |

- `wall_seconds`はプロセス起動込みの経過時間です。C区間にはCSVのI/Oも含みます。
- `peak_rss_bytes`はLinuxの`wait4`が返すプロセスの最大RSSです。親の累積RSSではありません。
- 小さいCではexec前の高水位・起動オーバーヘッドなどが目立ちます。小さいLの一定RSSを格子メモリと同一視しないでください。
- `sampled_peak_rss_bytes`は監視で見つけたRSSであり、短時間のピークを取り逃すので、最大RSSの正本にはしません。
- 段階は逐次実行です。PCに必要なピークを考えるとき、3段階の最大RSSを足しません。
- 描画の`read_validate_seconds`と`render_save_seconds`は内部時間です。後者にはMatplotlibの初回importとPNG保存を含みます。
- ウォームアップなし・OSページキャッシュは消去しません。異なるseedのばらつきには配置・構造の差も含まれます。
- ミリ秒程度の速度を詳しく比較する場合、`repeats`を増やして同じseedを繰り返してください。

描画は初期設定で1,000分子以下、Python後処理は50,000分子以下に限定します。
上限を超えた段階は`skipped / molecule_limit`と記録し、Cの測定は行います。値は設定で変更できます。
描画は全実空間・全グラフ・代表最大グラフ・代表最大実空間の4枚です。

## どの表を見るか

| ファイル | 内容 |
|---|---|
| `summary.csv` | L・目標占有率・段階別の成功数、未達数、省略数、時間/RSSの中央値・最小・最大 |
| `stages.csv` | 1試料×1段階の生の時間・RSS・終了状態 |
| `cases.csv` | 試行回数・実占有率・最大クラスタ・元CSV容量・gzip容量・保存量 |
| `files.csv` | 各CSVの元バイト数・gzipバイト数・SHA256・保持形式 |
| `environment.json` | CPU、OS、Python、Matplotlib、メモリ、検出できたcgroup情報 |
| `benchmark.json` | 設定実行の状態、コード情報、バイナリSHA256、開始終了時刻 |
| `build.log` / `source.zip` | コンパイルコマンド・ビルドログとソースの控え。試料ごとの重複保存はしない |
| `runs/<試料>/performance.json` | その試料の全測定・状態・ファイル情報 |
| `runs/<試料>/run.json` | 既存グラフ後処理と接続するための最小限の状態情報 |

`summary.csv`の時間・RSS集計は、**その段階が正常完了した値だけ**を使います。
未達や資源制限による短い終了時間を成功の平均へ混ぜません。生値は残します。
`raw_csv_bytes`と`gzip_csv_bytes`はCが出力した元の7 CSVだけの合計です。
派生CSVの容量は別列、PNG・ログ・JSON・ソースも含めた保存量は`saved_bytes`です。
`saved_bytes`は測定終了時のスナップショットであり、その後に復元や追加入力すると現在容量は変わります。

図を作る場合：

```bash
python3 scripts/plot_benchmark.py data/benchmarks/<実行フォルダ> \
  --output data/benchmarks/<実行フォルダ>/resources.png
```

既存の画像は上書きしません。図を後で追加した容量は元の`saved_bytes`に含まれません。

## 容量を抑えて残す・復元する

初期設定は`retention: "gzip"`です。全てのCSVを圧縮し、**復号したバイト列のSHA256が元と一致した後**に、
その試料で作った元CSVを圧縮版へ置換します。既存の別実行データは変更しません。
設定・集計・ログ・PNGはそのまま残します。圧縮レベルは初期値1で、容量と圧縮時間を併記します。
`retention: "raw"`にするとCSVを残し、比較測定用のgzipは照合後に破棄します。

ビューアや従来のPythonツールで使う試料だけ復元します。

```bash
python3 scripts/benchmark.py --restore data/benchmarks/<実行フォルダ>/runs/<試料>
```

空き容量とハッシュを検査します。同じ内容の既存CSVは変更せず、内容が違う既存ファイルは上書きしません。
復元後には圧縮版と非圧縮版の両方が存在するので、その分の容量が増えます。

## 負荷の上限とPC・サーバの判断

初期設定：1段階60秒、最大RSS4 GiB、1試料512 MiB、全体1 GiB、空き容量を2 GiB残します。
上限超過・実行失敗で以後の試料を止め、既に得た結果を集計して保存します。未達だけの場合は次の試料へ進みます。
試行上限は`max(10000, 100 × 目標分子数)`で、固定1万回による大きい系の早期未達を避けます。

RSS・ディスク使用量は短周期のサンプリング監視です。急増による一時超過を完全には防げず、OSのハード制限ではありません。
Cの事前メモリ見積りは格子・末端索引・分子・軌跡の基本領域のみです。候補・結合・UF・Pythonの領域を別に使います。
cgroup情報は検出できた範囲で記録し、WSLの設定がWindowsの搭載メモリより小さい場合も考慮してください。

最初の結果を見て、設定を`configs/local/benchmark-next.json`へコピーし、L=192,256へ広げます。
それでも余裕がある場合に384,512へ進めます。上限を増やす場合は、**1試料の負荷と全条件の合計**を見て判断します。

- 1試料のRSSが小さくても、全条件が長時間になる場合はサーバでまとめて実行する。
- WSLを含む実際の空きメモリが不足する、PC操作が重い、スワップが増える場合は拡大を止める。
- Cが軽く、後処理・描画だけが重い場合は、全試料を描かず代表試料に絞る。
- サーバで並列実行するときは、1試料のRSS×同時実行数に余裕を加えてジョブのメモリを申請する。

## 検証

```bash
make test-benchmark
```

通常のrun_demoとのCSV一致、同一seedの再現性、未達の除外、段階別描画計測、時間・RSS・容量上限での停止、
gzip往復・復元時の非上書きを検証します。`make test`の物理モデルの検証は従来どおりです。

測定例と元の集計表は[初期ベンチマークの例](benchmark-example/README.md)を参照してください。これはCodex環境の結果です。
