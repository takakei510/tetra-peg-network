# H₂とクラスタサイズの検証：2026-10-27の整理・実行手順

**保存容量対策の更新：[h2-storage.md](h2-storage.md)を優先。標準はcompact、新しい保存先でcapacityの18試料から確認する。**

## 問いと仮説

問い：同じL・実占有率の条件で、小さいクラスタほどH₂に関わる末端割合が高いか。
仮説：同一分子ペアへの二重結合が末端を使い、異なるクラスタへの接続機会を減らす可能性がある。
未観測の仮説であり、今回の実装完了は仮説が正しいという意味ではない。
最終状態の相関だけから因果や成長速度は決められない。別の分子への結合も、相手が同じクラスタならクラスタサイズを増やさない。

## 5点の説明

|項目|今回の説明|
|---|---|
|目的|クラスタサイズと局所的な二重結合の多さとの関係を確認する|
|定義|横軸は分子数sの固定サイズ区間（1、2、3–4、5–8…）。縦軸はh₂/s。無次元。1ペアは4末端を使い、全末端4sで割るため。H₂=0のクラスタ・孤立分子も含める|
|計算|bonds.csvを分子ペアごとに数え、ちょうど2本なら1。BFSでクラスタを独立再構築し所属へ割り当てる。各試料内でサイズ区間別にクラスタを等重みで平均し、その値をseed間で等重みに平均する|
|観測|PCで実験するまで未確定。サイズごとの値・誤差・有効試料数を確認し、傾向が逆でもそのまま報告する|
|限界|h₂/sの分母sによる見かけの相関、希少な大クラスタ、サイズ区間幅、最大クラスタの影響、生成モデルの偏り。SD/SEはこれらの偏りを解消しない|

個数h₂もclusters.csvに保存する。大クラスタは単に分子・結合が多いため、個数の大小だけで比較しない。
サイズ区間内の全末端を等重みとしたsum(h₂)/sum(s)も各試料result.jsonに保存するが、主図の「クラスタ等重み平均」とは異なる。
空の区間は0ではなく欠測。有効試料数samples_with_binを必ず見る。n=1のSEは未定義。
同じ試料の多数のクラスタを独立なseedとして誤差を小さく見積もらない。
主図は全クラスタを含む。最大1個除外も併記。同率最大は最小cluster_idの1個を除外する。
孤立分子の値は構造上必ず0なので「小さいほど高い」が全域で単調に成立するとは限らない。

## 実装・データの流れ

- 生成：既存benchmark.run_case → C生成・結合・Union-Find → 原CSV。生成規則は変更しない。
- 独立検証：Python BFS（全分子を頂点とし孤立分子を保持）でCのcluster-summary / cluster-membersとサイズ・所属・結合次数を照合。
- 既存解析：analyze_caseで設定、目標達成、結合末端の重複・所有者、A–B、距離、Hₖ、モーメントを照合。
- H₂：無向分子ペアの結合数が「ちょうど2」。H₃/H₄内の閉路は今回含まない。
- 全体の末端率p=E/(2N)、H₂全末端割合H₂/N、結合済み末端割合2H₂/E。比は試料ごとに計算する。
- 生のKとK/L³を保存・作図。Sfinも従来定義で再測定する。N/Kは既存解析の付随値として保存するが新規主図にはしない。
- 保持対象の原CSVは復号ハッシュ検証済みgzipで保持。後日4・6分子サイクルを解析するため結合CSVを削除しない。

## PCで実行（WSL）

```bash
cd ~/tetra-peg-network
git pull --ff-only
python3 tests/test_h2_relation.py
python3 scripts/run_h2_validation.py plan --samples 100
# まず最も大きいL128、Φ0.44で3試料。時間・保存容量・検証の確認用。
python3 scripts/run_h2_validation.py pilot --samples 3 --workers 2
```

pilotの結果ZIPを確認した後、同じ保存先で各条件100試料へ進む。

```bash
python3 scripts/run_h2_validation.py run --samples 100 --workers 2
# 同じseedを再生成せず、各条件の総数を500へ拡張する例
python3 scripts/run_h2_validation.py run --samples 500 --workers 2 --max-storage-gib 50
```

標準条件：L=32/64/128、Φ=0.10,0.20,0.30,0.40〜0.50(0.01刻み),0.60,0.70。
16占有率×3サイズ=48条件。100試料で4,800、500で24,000、1,000で48,000試料。
全条件を100以上で比較し、収束を確認して必要な範囲を絞る。100試料を十分と断定しない。
独立seed追加を優先し、同じseedのrepeatを独立試料として水増ししない。
seedは固定namespace・L・Φ・試料番号のSHA256先頭64bit。増分・並列順に依存せず、同一計画内の衝突も検査する。
旧240試料とは混合しない。新実験の対照として旧結果を別に比較できる。

標準保存先data/validation/h2_relation_compact。新設定は--config、別保存先は--output。
試料数・worker数・保存予算だけを増やして再開できる。モデル設定やコード/バイナリが変わったら別保存先が必要。
workersはCPU数と検出空きメモリから制限。各C処理最大600秒/RSS1024MiB、1試料512MiBの出力監視。
並列単位は条件×seed。プロセスごとにCSV解析も行う。ビルドは親プロセスで1回行う。
これは平衡SAWの一様抽出ではなく、現在のkinetic-growth生成モデルの統計である。

無制限に試料を作るのではなく、時間・メモリ・保存容量を測って拡張する。
既定20GiBのstudy保存予算、空き2GiB、実行中workerの一時出力予約を監視する（厳密なOS割当ではない）。
長期実行では原CSVが大きいため、pilotのwall_seconds・保存容量から必要予算を見積もる。
容量制限・失敗時は追加投入を止め、完了済みの部分結果を出力する。成功試料だけの偏った集計を完成結果とは呼ばない。
失敗試料を別seedに置き換えない。原因確認後--retry-failedで失敗フォルダを退避し、同じseedを再試行する。
強制終了後も完了済みresult.jsonはハッシュ照合して再利用。ファイルロックはOSが解除する。
Ctrl-Cでは実行中workerの終了を待つ場合がある。途中CSVを手動削除しない。

保存済み結果だけの集計：

```bash
python3 scripts/run_h2_validation.py analyze --samples 100
```

## 出力と検証判断

- cases/<条件・番号>/runs/：結合・所属・各summary・performance.json。compactでは軌跡と全候補は省略。
- cases/<条件・番号>/clusters.csv.gz：1クラスタ1行。size, bonds, h2, h2/s, 2h2/e, p。
- result.json：試料統計・サイズ区間集計・入力と出力のSHA256・条件。
- 全試料連結cluster_samples.csvは作成しない。正本は試料別clusters.csv.gz。
- samples.csv / summary.csv：1試料/1条件。全体H₂、K、Pmax、S1、Sfin、SD・SE・有効数。
- size_relation.csv：同じL・Φのサイズ区間別の平均・SD・SE、寄与seed数とクラスタ数。
- convergence.csv：先頭5/10/20/50/100/200/500/1000/最終nで平均・SD・SEを再計算。
- manifest.json：requested/completed、partial/completed、定義、コードとバイナリ情報。
- upload_h2_validation.zip：結果CSV・図・manifest。結合などの保持対象原CSVはPCに残す。compactでは軌跡・候補は保存しない。

Matplotlibがある場合のみ図を作成。なければCSV/ZIPは完成し、その旨をmanifestに記録する。
新規図は測定点＋SEのみ。補間・fit・接続線なし。n=1はSEを描けない。
旧PPTの補間設定は今回確認できていないので、旧曲線の凹みを物理的傾向と決めつけない。

判断：試料数増加による平均の変化とSE、L間の差・交差・Sfinピークの安定性を確認する。
SDは試料そのもののばらつきで、nを増やしてゼロにするものではない。
希少サイズ区間の欠測、h₂/sの数学的制約を確認してから関係を解釈する。因果検証や4/6分子サイクル実装は次段階。
図を追加・解釈する前に、ユーザー自身が上記5点を説明できるか確認する。
